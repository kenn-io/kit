# Huma Checker Instructions

## Scope

`tools/humacheck/` is the type-aware checker behind `cmd/huma-check`. It
enforces the shared Huma contract across kenn-io Go modules:

- `jsonv2`: no production Go file in the module imports `encoding/json` (v1),
  and a module that builds a Huma API writes at least one `huma.Format`
  whose Marshal and Unmarshal reach `encoding/json/v2` into a Formats map
  (`config.Formats["application/json"]`, a map literal entry, or
  `huma.DefaultFormats["application/json"]`). Huma's own defaults encode
  with v1 inside the huma package, so a clean import graph alone is not
  enough; without the install, payloads keep v1 semantics (nil slices as
  `null`). Assigning `huma.DefaultJSONFormat` alone installs nothing:
  `huma.DefaultFormats` copied the v1 value at package init and
  `huma.DefaultConfig` reads the map, so the variable only counts once it is
  written into a map. Both checks are module-wide; which API a format
  reaches is not tracked.
- `spec`: OpenAPI 3 documents tracked in the repository are YAML, and a module
  that builds a Huma API commits at least one under its own module directory.
  Documents under sibling or nested modules do not count.
- `generator`: the standard client generator is declared somewhere in the
  repository: orval for TypeScript, oapi-codegen-dd v3 for Go. Any other
  generator is reported where it is declared so toolchains do not fragment;
  `// indirect` go.mod lines do not count as a declaration. Generated Go
  files are judged by the tool named in their `Code generated by` header.
- `client`: string literals naming one of the module's own routes are reported
  when they flow into request-building code.
- `frontend`: the same route match over `fetch`-style calls in browser sources.

`cmd/huma-check` only wraps `Run` for CLI use.

## Analyzer Rules

- Keep the Go rules type-aware through `go/packages` and `go/types`; never
  fall back to text matching for Go code. Repository rules (`spec`,
  `generator`, `frontend`) are intentionally text-based over tracked files.
- Loading uses one `packages.Load` over the caller's patterns so functions in
  any module package can be followed by `*types.Func` identity. Do not switch
  to `go/analysis` facts: the client rule needs route inventory from packages
  the client does not import.
- Tests (`_test.go`), generated files (`ast.IsGenerated`), and `generated/`
  directories are never judged by the semantic Go rules or the import ban.
  Extend `skipFile` rather than adding per-rule exceptions. The one explicit
  exception is provenance: the `generator` rule reads a generated Go file's
  `Code generated by` header to learn which tool produced it, and ignores
  everything else in the file (including `go:generate` lines); files under
  `generated/` without a header contribute nothing.
- Construction sites and route inventory come from `eachRoot`: function
  bodies and package-level variable initializers alike, so
  `var api = humago.New(...)` counts. The JSON format search walks whole
  files for the same reason.
- The import ban parses every tracked `.go` file under the module directory
  (`parser.ImportsOnly`) instead of the loaded packages, so files excluded
  by build tags or platform suffixes are covered and staged content is what
  gets judged.
- A format referenced through another module package
  (`codecs.JSONFormat`) is judged in its defining package via
  `packageByPath`.
- Package patterns stay: `huma-check ./cmd/api` judges the selected packages
  plus their in-module dependencies, and the user rejected forcing whole-
  module loading. The import ban is always module-wide because it reads
  tracked files.
- The JSON rule deliberately has no value tracing. An earlier version followed
  each `huma.Config` to its construction call and was reworked twice over
  ordering and branch corner cases; the user chose the module-wide import
  search plus the format-install existence check instead. Do not reintroduce
  per-call config tracing. The format-install check only follows Marshal and
  Unmarshal bodies (and thin local wrappers) to `encoding/json/v2`; `no`
  still needs a positively identified v1 codec.
- Route inventory records the receiver kind of each registration: a
  `*huma.Group` receiver composes as adapter prefix + group prefix + path, a
  plain API receiver as adapter prefix + path, and a receiver that arrived as
  a function parameter (or a standalone Operation literal) composes both
  ways. Which group or adapter a path belongs to is still not tracked, so
  with several groups their prefixes can combine; keep that limitation
  documented in `collectRoutes`.
- Requesters and registrars are flow sets of parameter indexes: a string
  parameter is interesting only when it reaches a URL or path position. Only
  those argument positions are inspected at call sites.
- Inside Git, every rule judges the index. Repository rules read file
  contents through `indexFS`, and `Run` feeds `go/packages` an overlay with
  the index content of every tracked Go, go.mod, go.sum, or go.work file
  whose working-tree copy differs (`git diff-files`). Untracked files and
  files removed from the index but left on disk are outside what an overlay
  can express and still come from the working tree; say so rather than
  claiming a fully staged snapshot. The directory walk is only for checkouts
  outside Git.
- Files are read whole. There are no scan-size limits; the user rejected
  them.
- A tracked file the rules cannot read fails the run. Never skip a file and
  return success.
- Git subprocesses run with inherited `GIT_DIR`/`GIT_INDEX_FILE`/
  `GIT_WORK_TREE` stripped (`gitenv.StripInherited`) so the checker binds to
  the directory it was given; a parent hook exporting those variables must
  not redirect it, and tests under such a hook would otherwise read the outer
  repository.
- Generator declarations are matched as whole tokens on non-comment lines;
  hand-written Go files contribute only `//go:generate` directives, generated
  Go files contribute only their header line, and go.mod skips `// indirect`
  lines. oapi-codegen-dd stamps the bare `Code generated by oapi-codegen.`
  header, which counts as the standard generator.
- The frontend scan locates calls in a view of the source with comments and
  string contents blanked (`maskSource`), then reads the first argument from
  a view with only comments blanked. Both views keep the original length and
  newlines so offsets and line numbers stay valid.

## Tests

- Go fixtures live under `testdata/src` in GOPATH mode with stub `huma` and
  `humago` packages. Assert diagnostics with `// want "regexp"` comments; the
  comment is not a Go string, so escape regexp metacharacters once.
- Repository rules are tested with `testing/fstest` maps; never depend on git
  state or the user's environment.
- Index and overlay behavior is tested against temporary repositories from
  `go.kenn.io/kit/git/test`; the overlay test uses a stdlib-only module so it
  loads offline.
- When a diagnostic message changes, update the fixture comments and
  `repo_test.go` expectations in the same change.
- Validate precision changes against real kenn-io repositories before
  relaxing or tightening a rule; the fixtures cover shapes seen there.
